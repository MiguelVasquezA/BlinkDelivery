# Requisitos, Preguntas y Supuestos del Proyecto

## Proyecto: Plataforma de Domicilios

### Descripción General

El proyecto consiste en el diseño de una base de datos para una plataforma de domicilios que permita gestionar la información relacionada con clientes, restaurantes, productos, pedidos, direcciones de entrega, domiciliarios y calificaciones.

La plataforma busca centralizar la información necesaria para que los clientes puedan consultar restaurantes y productos, realizar pedidos, realizar seguimiento al estado de sus compras y registrar calificaciones sobre los establecimientos utilizados.

Por su parte, los restaurantes podrán administrar la información de sus productos y disponibilidad, mientras que los domiciliarios estarán asociados a los pedidos que deben entregar.

La solución permitirá mantener la información organizada y relacionada mediante una estructura de base de datos consistente que facilite consultas, seguimiento de pedidos e identificación de información relevante para la operación del sistema.

---

# Requisitos Funcionales

## RF01. Gestión de Clientes

El sistema deberá permitir registrar clientes con información de identificación, contacto y datos básicos necesarios para la realización de pedidos.

---

## RF02. Gestión de Direcciones

El sistema deberá permitir que cada cliente registre una o más direcciones de entrega.

Las direcciones registradas podrán ser utilizadas posteriormente al momento de realizar un pedido.

---

## RF03. Gestión de Restaurantes

El sistema deberá permitir almacenar y consultar información relacionada con los restaurantes registrados dentro de la plataforma.

Cada restaurante podrá contar con categorías, productos, calificaciones y estados de disponibilidad.

---

## RF04. Gestión de Categorías

El sistema deberá permitir clasificar los restaurantes mediante una o varias categorías de comida.

Ejemplos:

- Comida rápida
- Hamburguesas
- Pizza
- Comida saludable
- Postres
- Bebidas

---

## RF05. Gestión de Productos

El sistema deberá permitir registrar productos asociados a un restaurante.

Para cada producto se deberá almacenar información como:

- Nombre
- Descripción
- Precio
- Disponibilidad

---

## RF06. Consulta de Productos

El sistema deberá permitir a los clientes consultar los productos disponibles de un restaurante antes de realizar una compra.

---

## RF07. Creación de Pedidos

El sistema deberá permitir a los clientes realizar pedidos seleccionando productos de un restaurante.

Cada pedido deberá quedar asociado al cliente que lo realizó.

---

## RF08. Detalle de Pedido

El sistema deberá almacenar los productos incluidos en cada pedido junto con sus respectivas cantidades.

---

## RF09. Seguimiento de Pedido

El sistema deberá permitir consultar el estado actual de un pedido.

Algunos estados posibles son:

- Pendiente
- Aceptado
- En preparación
- Listo para recoger
- En camino
- Entregado
- Cancelado

---

## RF10. Gestión de Domiciliarios

El sistema deberá permitir registrar domiciliarios encargados de realizar las entregas.

---

## RF11. Asignación de Domiciliarios

El sistema deberá permitir asociar un domiciliario a un pedido para efectuar la entrega correspondiente.

---

## RF12. Historial de Pedidos

El sistema deberá permitir consultar el historial de pedidos realizados por cada cliente.

---

## RF13. Calificaciones

El sistema deberá permitir que los clientes registren calificaciones sobre los restaurantes después de haber recibido un pedido.

Cada calificación podrá incluir:

- Puntuación
- Comentario
- Fecha

---

## RF14. Consulta de Calificaciones

El sistema deberá permitir consultar las calificaciones asociadas a cada restaurante.

---

## RF15. Disponibilidad

El sistema deberá permitir administrar la disponibilidad tanto de restaurantes como de productos.

---

# Requisitos No Funcionales

## RNF01. Integridad de Datos

La base de datos deberá garantizar la consistencia de las relaciones entre todas las entidades del sistema.

---

## RNF02. Persistencia

Toda la información almacenada deberá mantenerse disponible entre sesiones del sistema.

---

## RNF03. Escalabilidad

La estructura deberá permitir la incorporación de nuevos clientes, restaurantes, productos y pedidos sin modificaciones significativas del modelo.

---

## RNF04. Disponibilidad

La información almacenada deberá estar disponible para consulta cuando sea requerida por los usuarios autorizados.

---

## RNF05. Mantenibilidad

La base de datos deberá diseñarse siguiendo buenas prácticas de modelado para facilitar futuras modificaciones.

---

## RNF06. Seguridad

La información deberá almacenarse de manera organizada evitando inconsistencias y accesos no autorizados.

---

# Preguntas de Análisis y Decisiones Tomadas

## ¿Un cliente puede tener varias direcciones?

Sí. Un cliente puede registrar múltiples direcciones, por ejemplo:

- Casa
- Trabajo
- Universidad
- Otra ubicación frecuente

---

## ¿Un restaurante puede tener muchas categorías?

Sí. Un restaurante puede ofrecer diferentes tipos de comida y estar asociado a varias categorías.

---

## ¿Un producto pertenece únicamente a un restaurante?

Sí. Cada producto pertenece exclusivamente al restaurante que lo registra.

---

## ¿Un cliente puede realizar varios pedidos?

Sí. El sistema almacenará el historial completo de pedidos realizados por cada cliente.

---

## ¿Un pedido puede incluir productos de diferentes restaurantes?

No. Cada pedido estará asociado a un único restaurante.

---

## ¿Un pedido puede tener más de un domiciliario?

No. Cada pedido tendrá como máximo un domiciliario responsable de la entrega.

---

## ¿Quién puede calificar a quién?

Los clientes podrán calificar restaurantes después de completar una compra.

---

## ¿Se puede calificar un restaurante sin haber comprado?

No. Las calificaciones estarán restringidas a clientes que hayan realizado pedidos en dicho restaurante.

---

## ¿Los restaurantes y productos pueden manejar estados?

Sí.

Los restaurantes podrán encontrarse:

- Abiertos
- Cerrados

Los productos podrán encontrarse:

- Disponibles
- Agotados
- No disponibles

---

## ¿Se almacenará el historial completo de ubicación del domiciliario?

No.

Para el alcance inicial únicamente se almacenará la información necesaria para realizar el seguimiento del pedido y la entrega.

---

# Supuestos del Proyecto

## SP01

Todos los clientes deben estar registrados antes de realizar pedidos.

---

## SP02

Todo restaurante debe tener al menos una categoría asociada.

---

## SP03

Todo producto debe estar asociado a un restaurante.

---

## SP04

Todo pedido debe tener al menos un producto.

---

## SP05

Todo pedido debe estar asociado a una dirección de entrega.

---

## SP06

El seguimiento de pedidos se realizará mediante estados del pedido y no mediante geolocalización en tiempo real.

---

## SP07

Las recomendaciones inteligentes de restaurantes o productos serán consideradas una funcionalidad opcional.

---

## SP08

Los identificadores de las entidades serán únicos dentro del sistema.

---

## SP09

La base de datos conservará el historial de pedidos y calificaciones.

---

## SP10

La plataforma estará enfocada principalmente en la experiencia del cliente durante la búsqueda, selección y solicitud de productos.
